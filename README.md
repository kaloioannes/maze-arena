# Maze Arena · 迷宫竞速实验室

**每一种思考，都有自己的出路。**

[打开实验室](https://kaloioannes.github.io/maze-arena/) · [公开源码](https://github.com/kaloioannes/maze-arena)

一个纯前端、中文界面的迷宫算法游乐场。生成同一座迷宫，让不同的策略真实运行，观察搜索前沿、回溯、候选队列与最终路线。

## 可以玩什么

- **7 种地图生成器**：递归回溯、随机 Prim、随机 Kruskal、Wilson、递归分割、Sidewinder、二叉树。
- **17 个真实算法选项**，包含经典图搜索、局部行走与 3 位彩蛋选手。
- 自定义种子、4–1024 的宽高、环路密度、开放房间与代价 1–9 的地形；上限 **1,048,576 格**。
- **独奏 / 对照 / 竞速**：最多 4 位选手；暂停、单步、10–50,000 逻辑步/秒。
- **算法驾驶舱**：实时 g/h/f、同步执行摘要、候选队列或栈、前沿曲线、事件记录、节点探针。
- 可缩放与拖动的 Canvas、巨图小地图、拖动或重新放置起终点、探索粒子、路径辉光、抵达光环、可选音效。
- 版本化分享链接，复现地图、算法组合、模式与起终点。
- 独立性能测试：预热 1 次、正式 3 次、中位数报告、JSON 导出。
- 画布 PNG 导出、键盘操作、响应式布局与减少动态效果模式。

## 算法阵容

| 信息条件 | 算法 |
| --- | --- |
| 全图搜索 | BFS、DFS、Dijkstra、A*、加权 A*（2.5）、贪心最佳优先、双向 BFS、迭代加深 DFS、IDA*、束搜索（宽度 32） |
| 局部行走 | 左手法、右手法、Trémaux 通道标记 / 回溯、随机游走 |
| 彩蛋 · 局部行走 | 头铁哥（直行优先回溯）、好奇宝宝（最少访问优先）、命运轮盘（随机次序回溯） |

图鉴明确标注适用条件、完备性与最优性，不把算法变体包装为全新的学术算法。

## 如何理解成绩

**探索赛是策略演示，不是 CPU 跑分。** 图搜索通常以一次节点展开为逻辑步；迭代搜索也计入回溯；行走策略计入实际移动（初次进入也计一步）。根据这些事件计数排名。不同信息条件分组展示，避免让知道全图的搜索算法与局部行走混排。

- 「已探索」：访问过的不同格子，重复访问不重复计数。
- 「路线」：全图搜索得到的路径；行走策略保留真实回头路。
- 「路线代价」：进入每个格子的代价之和，起点不收费。
- 主画面「计算用时」：Worker 内推进算法的累计时间，排除绘图和通信，但会受分批运行与其他线程影响。
- **性能实验室**：暂停视觉比赛，用单独 Worker 顺序运行选手。每个算法先预热，再测 3 次并报告中位数；计时包含数据结构更新与事件记录，排除地图生成、引擎初始化、绘图与消息传输。这是本实现、当前设备上的表现，不是算法理论速度的绝对排名。

普通探索预算为 `max(250000, min(格数 × 40, 10000000))` 个逻辑事件。基准测试最多 200 万事件、单次约 1.8 秒。循环、候选裁剪、不可达、步数预算与时间预算都有独立状态；未完成者不计入成功排名。

## 本地开发

需要 Node.js 24 与 pnpm 11.25.0。

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
pnpm preview
```

源文件使用 TypeScript；生产构建是普通静态文件，`base: './'` 支持 GitHub Pages 的仓库子路径。无服务端、无运行时 API 密钥、无用户账号。

## 架构

```text
src/maze.ts     种子随机数、通道位图、七种生成器
src/engine.ts   可单步执行的算法引擎、队列与堆、探针数据
src/worker.ts   后台生成、算法推进、顺序基准测试
src/render.ts   分层 Canvas、按缩放级别绘制、粒子与路径
src/catalog.ts  算法图鉴、性质与执行摘要
src/ui.ts       语义化界面、内联图标、文本处理
src/main.ts     交互、运行控制、分享与导出
tests/         生成结构、独立最短路参考与运行一致性校验
```

每格用 4 位表示四向通道；权重存于 Uint8Array。每位选手拥有独立 Worker 和引擎状态。地图生成可通过终止 Worker 立即取消。巨图使用有限分辨率的底图与探索层，放大后根据可视范围绘制墙体，不创建百万级 DOM。

## GitHub Pages

仓库为公开仓库。`.github/workflows/pages.yml` 在 main 分支更新后自动：安装依赖 → 测试 → 类型检查与构建 → 发布 Pages。

新建副本时，在仓库 **Settings → Pages → Source** 中选择 **GitHub Actions**。站点无需后台服务。

## 验证与规模

- 16 项引擎测试：7 种生成器的连通性 / 通道对称性 / 生成树性质 / 确定性；17 种策略的合法行为；独立 O(V²) 最短路参考；60 张带环地图的双向 BFS 最短步数；随机策略复现；不可达与预算；单步和批量一致性；双向节点探针。
- 在 Windows / Node.js v24.22.1 上，7 种生成器均生成了 1024² 的加权带环地图，A* 均完成合法寻路。生成约 0.14–2.97 秒，搜索推进约 0.77–1.16 秒。此处是单次引擎规模检查，**不包含浏览器绘图，不代表其他设备表现**。
- 浏览器端检查包含竞速、对照、单步、算法选择上限、性能报告、自定义加权地图、起终点编辑、探针、分享链接恢复、手机布局和百万格运行。
